# Pathbridger 0.2.5 repair QA

## Confirmed failures and repairs

1. Pathbuilder currently loads `Pathbuilder2eWebRemastered111k.js`. The adapter
   accepted only v109g. The inspected v111k source also moves both export POSTs
   from `pathbuilder2e.com/app/` to `pathbuilder-backend.com/app/builds/`.
   The adapter now recognizes both inspected versions and exact endpoints.
   Unknown versions still fail closed; automatic exports never call native send.
2. `load()` checked no edit state after awaiting the background library. A refresh
   initiated before a paste/file selection could finish afterward and clear the
   source field. Edit/request generations now prevent stale refreshes from
   replacing edits. Four new regression cases fail with the original options.js
   (the observed value becomes an empty string) and pass with the repaired file.
3. Sequential optional Nethys lookups could delay import by 15 seconds per entry.
   Import now shows nearby progress, supports skipping remaining lookups, stops
   on service failure, and limits lookups to 20 seconds overall. Cache errors
   retain imported rolls. Invalid, empty, link, and internal-save inputs receive
   specific recovery instructions. File reading and import protect their inputs.

## October 18 idle-hang investigation (0.2.6)

The user reported hangs during idle/general browsing. Found a feedback loop:
Paizo content scripts request `characters` on startup and on library changes,
but the background handler persisted the library for that read request. Firefox
can emit storage changes even when the written data is unchanged, restarting
the requests in every open Paizo tab. The earlier QA missed this interaction.
See [Mozilla's storage event note](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/API/storage/onChanged).

The fix treats both `library` and `characters` as reads, persisting only for
initial migration. Real edits and sync operations retain the existing writes.
Regression tests run the actual background and Paizo content scripts with
Firefox-style unchanged-key events. Before the fix, three idle tabs generated
93 reads before the harness cutoff; afterward they settle at three reads and
zero writes. A real edit triggers one refresh per tab and one storage write.
Both new tests failed before the fix. All 82 tests now pass. Firefox packaging
has zero errors and the same two existing warnings. Only background.js and
manifest.json differ from the signed 0.2.5 file contents.

Live diagnostics: Zen PID 96650 was initially around 88% CPU. The user disabled
Pathbridger themselves; the first subsequent sample still showed 86% CPU.
A later five-second interval fell from 74% to 2.8%. The three-second native
stack sample at 13:38 Pacific recorded a 16.7 GB physical footprint and 43.9 GB
peak; subsequent top output fell to about 14 GB. This is consistent with
accumulated work/memory taking time to clear, but does not establish that all
of the browser's memory came from this extension. Most XUL stack frames are
unsymbolicated, so the native sample cannot identify a specific JS handler.
No browser restart, tab reload, character change, or draft modification was
performed. Keep 0.2.5 disabled until the corrected signed update is installed.
